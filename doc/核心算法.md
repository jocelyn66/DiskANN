把 DiskANN 想成一张城市路网：每个向量是路口，图边是道路。`R` 限制每个路口最多连几条路，`L` 是导航时同时保留的候选路线数，`alpha` 决定是否保留一些“绕一点但跨区域”的长程路。磁盘版则是：完整地图放 SSD，内存里只放 PQ 压缩版“缩略图”，用缩略图决定往哪走，走到关键节点时再从 SSD 取详细信息。

```text
构建内存 Vamana 图
raw vectors
  -> Index::build()
  -> build_with_data_populated()
  -> generate_frozen_point() / medoid start
  -> link()
      -> search_for_point_and_prune()
          -> iterate_to_fixed_point()   // 找候选邻居
          -> prune_neighbors()
              -> occlude_list()         // RobustPrune 的核心判定
      -> inter_insert()                 // 加反向边
      -> final cleanup                  // 超度数节点再剪枝

磁盘索引
raw vectors
  -> build_disk_index()
      -> generate_quantized_data()      // 内存 PQ codes
      -> build_merged_vamana_index()
      -> create_disk_layout()           // SSD: [coords | degree | neighbors]

查询
memory: Index::search() -> iterate_to_fixed_point() -> top K
disk:   PQFlashIndex::cached_beam_search()
          -> PQ 引导候选
          -> cache 命中或 SSD batch read
          -> 可选 full precision reorder
```

**1. 内存核心：Vamana 图**
构建入口在 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:1524)。`build_with_data_populated()` 初始化 scratch、生成 frozen point，然后进入 `link()`。起点来自 medoid 或 frozen point：`calculate_entry_point()` / `get_init_ids()` 在 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:733)。

`link()` 是建图主循环，位置在 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:1286)。它并行遍历节点，对每个点调用 `search_for_point_and_prune()` 找候选并剪枝，然后 `set_neighbours()` 写出边，再用 `inter_insert()` 给邻居补反向边。最后还有 cleanup，把度数超过 `R` 的节点重新剪一次。

参数来自 `IndexWriteParameters`：[include/parameters.h](/Users/jo/workspace/index/DiskANN/include/parameters.h:16)。

- `R / max_degree`：每个点最多保留多少邻居。越大召回越高，但图更大，内存和磁盘 I/O 都上升。
- `L / search_list_size`：候选池大小。越大越不容易卡在局部最优，但比较次数和查询延迟会上升。
- `maxC / max_occlusion_size`：剪枝前最多看多少候选。大一些给剪枝更多选择，但构建更慢。
- `alpha`：剪枝松紧。大于 1 时更容易保留多样化/长程边，通常减少 hops，提高召回，但过大也可能让图边选择变“散”。

**2. 搜索核心：iterate_to_fixed_point**
`iterate_to_fixed_point()` 在 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:807)。它维护一个按距离排序的 `NeighborPriorityQueue`，队列实现见 [include/neighbor.h](/Users/jo/workspace/index/DiskANN/include/neighbor.h:23)。

流程很朴素但很关键：

1. 从 medoid/frozen start 初始化候选。
2. 取当前最近的未展开节点。
3. 读取它的邻居。
4. 对未访问邻居计算距离。
5. 插入候选池。
6. 直到没有未展开节点。

`Index::search()` 在 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:1975)，核心就是预处理 query 后调用 `iterate_to_fixed_point()`，再从候选池里取 top K。

**3. 剪枝核心：RobustPrune 在代码里的真实形态**
论文里的 `RobustPrune`，在这个仓库里主要拆成两层：

- `prune_neighbors()`：排序候选、必要时把 PQ 近似距离改回精确距离，再调用遮挡判定，见 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:1175)。
- `occlude_list()`：真正做 alpha 几何遮挡，见 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:1072)。

直觉是：如果候选 `b` 已经可以被更近的候选 `a` “覆盖”，那 `b` 这条边就不够有价值，可以剪掉。这样保留下来的不是单纯最近的 R 个点，而是“近 + 方向多样”的 R 个点。

`inter_insert()` 在 [src/index.cpp](/Users/jo/workspace/index/DiskANN/src/index.cpp:1216)。它把边反向插入邻居的 adjacency list；如果邻居度数超过 slack 阈值，就对那个邻居重新剪枝。这一步保证图不是一堆单向死路，而是更容易导航的路网。

**4. 磁盘版：PQFlashIndex**
磁盘构建入口是 [src/disk_utils.cpp](/Users/jo/workspace/index/DiskANN/src/disk_utils.cpp:1101)。关键流水线：

- `generate_quantized_data()` 训练 PQ codebook 并生成压缩向量，见 [src/pq.cpp](/Users/jo/workspace/index/DiskANN/src/pq.cpp:1095)。
- `build_merged_vamana_index()` 构建/分片/合并内存 Vamana 图，见 [src/disk_utils.cpp](/Users/jo/workspace/index/DiskANN/src/disk_utils.cpp:628)。
- `create_disk_layout()` 写 SSD 友好布局，见 [src/disk_utils.cpp](/Users/jo/workspace/index/DiskANN/src/disk_utils.cpp:847)：节点大体是 `[vector coords][neighbor_count][neighbor_ids]`，按 4KB sector 对齐。

磁盘查询核心是 `PQFlashIndex::cached_beam_search()`，见 [src/pq_flash_index.cpp](/Users/jo/workspace/index/DiskANN/src/pq_flash_index.cpp:1269)。它先加载内存 PQ codes 和 PQ pivots，加载入口在 [src/pq_flash_index.cpp](/Users/jo/workspace/index/DiskANN/src/pq_flash_index.cpp:758)。

查询时它不是一次读一个节点，而是：

1. 用 PQ 距离选 medoid 和候选。
2. 每轮从候选池取最多 `beam_width` 个未展开节点。
3. 先查 `_nhood_cache`，缓存命中就不用读盘，见 [src/pq_flash_index.cpp](/Users/jo/workspace/index/DiskANN/src/pq_flash_index.cpp:1432)。
4. 未命中的 frontier 组织成一批 `AlignedRead`，批量读 SSD，见 [src/pq_flash_index.cpp](/Users/jo/workspace/index/DiskANN/src/pq_flash_index.cpp:1478)。
5. 用内存 PQ codes 给邻居算近似距离，继续扩展。
6. 对已实际读到/缓存的节点，用全精度或 disk-PQ 数据进入 `full_retset`。
7. 如果启用 reorder，会对 top `k * 3` 做全精度重排，见 [src/pq_flash_index.cpp](/Users/jo/workspace/index/DiskANN/src/pq_flash_index.cpp:1618)。

**5. 最容易误解的点**
`PQ` 不是最终答案本身，它主要是“导航缩略图”。DiskANN 的巧妙点是：内存里用 PQ 省空间、快速决定走向；SSD 上保留图邻居和坐标信息；必要时再用 full precision reorder 把 PQ 的误差拉回来。

另外，`RobustPrune` 不是当前源码里的函数名。读这份代码时，把它映射成：

```text
RobustPrune ~= prune_neighbors() + occlude_list()
```

这条映射最稳。
