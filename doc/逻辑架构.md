## DiskANN 逻辑架构

### 类比：一座图书馆

把 DiskANN 想象成一座 **智能图书馆**：
- **书架**（DataStore）存放所有向量数据
- **索引卡片系统**（GraphStore）是一张邻居图，每本书都标注了"与我最相似的几本书"
- **图书管理员**（Index）知道怎么从入口出发，沿着图快速找到你要的书
- 当书太多放不进内存时，可以用**缩微胶卷**（PQ 压缩）把书压缩后存到磁盘上

### 核心分层

#### 1. 抽象接口层

| 抽象类 | 职责 |
|--------|------|
| `AbstractIndex` | 对外统一 API，通过 `std::any` 做类型擦除，屏蔽模板参数 |
| `AbstractDataStore<T>` | 向量数据的存取（加载、距离计算、预处理） |
| `AbstractGraphStore` | 图结构的存取（邻居列表的增删查改） |
| `Distance<T>` | 距离度量抽象（L2 / Cosine / InnerProduct，含 SIMD 加速变体） |
| `AbstractScratch<T>` | 搜索时的线程本地临时空间 |

#### 2. 两大索引实现

```
              ┌─────────────────────────────────────────────┐
              │             Index<T, TagT, LabelT>           │
              │                (内存索引)                     │
              │  ● 向量全量驻留内存 (InMemDataStore)          │
              │  ● 图全量驻留内存 (InMemGraphStore)           │
              │  ● 精确距离计算                               │
              │  ● 支持动态增删 (insert / lazy_delete)        │
              │  ● 支持标签过滤搜索                           │
              └─────────────────────────────────────────────┘

              ┌─────────────────────────────────────────────┐
              │           PQFlashIndex<T, LabelT>            │
              │               (磁盘索引)                     │
              │  ● 向量用 PQ 压缩后存于 SSD                   │
              │  ● 热点节点 (BFS 缓存) 驻留内存               │
              │  ● PQ 距离查表近似 + 异步磁盘 I/O             │
              │  ● 适合超大规模数据 (万亿级)                   │
              └─────────────────────────────────────────────┘
```

#### 3. 关键数据结构

- **`Neighbor`**：`{id, distance, expanded}` — 图遍历中的候选邻居
- **`NeighborPriorityQueue`**：有序维护 L 个最优候选，二分插入
- **`InMemQueryScratch<T>`**：搜索线程的**对象池**，包含候选池、visited 集合、距离缓冲等
- **`PQScratch<T>`**：PQ 距离查表的预计算空间（256 × num_chunks 的距离矩阵）

### 构建流程（Build Pipeline）

```
数据文件 ──→ DataStore.populate_data()
                   │
                   ▼
            计算入口点 (medoid)
                   │
                   ▼
     ┌─── OMP 多线程并行 ───┐
     │  对每个点:            │
     │  ① 从入口搜索 L 个   │    ┌─────────────────────┐
     │    最近邻            │    │  磁盘索引额外步骤:    │
     │  ② Occluding Links  │    │  ④ PQ 量化 (K-means) │
     │    剪枝到 R 个邻居   │    │  ⑤ 按扇区对齐写磁盘  │
     │  ③ 加反向边          │    │  ⑥ 缓存热点节点      │
     └─────────────────────┘    └─────────────────────┘
                   │
                   ▼
         .graph + .data + .tags 持久化
```

**Occluding Links 剪枝**：如果候选邻居 e 到 p 的距离，被某个已有邻居 n "遮挡"（即 dist(n→e) ≤ dist(p→e)），则 e 被剔除。参数 **alpha > 1** 放宽遮挡条件，保留更多路径多样性。

### 搜索流程（Search Pipeline）

```
Query ──→ 预处理 (归一化等)
              │
              ▼
      从入口点出发 (medoid)
              │
              ▼
    ┌── Greedy Beam Search ──┐
    │  while 候选池未耗尽:    │
    │    取距离最近的未展开点  │
    │    展开其所有邻居       │           磁盘索引差异:
    │    计算距离             │    ┌─────────────────────────┐
    │    插入优先队列         │    │ 距离用 PQ 查表近似       │
    │    更新 visited 集合   │    │ 未缓存节点 → 异步磁盘读  │
    └────────────────────────┘    │ 可选: 全精度重排序        │
              │                   └─────────────────────────┘
              ▼
        返回 Top-K 结果
```

### 并发模型

```
构建阶段:                              搜索阶段:
┌──────────────┐                     ┌────────────────────────┐
│  OMP 线程池   │                     │  ConcurrentQueue       │
│  #pragma omp │                     │  <InMemQueryScratch*>  │
│  parallel for│                     │  (预分配对象池)          │
│              │                     │                        │
│ 细粒度锁:    │                     │  每线程取一个 Scratch   │
│ _locks[i]   │                     │  搜索完归还, 零竞争     │
│ (per-point)  │                     └────────────────────────┘
└──────────────┘
```

- 构建时用 **OpenMP + 每点细粒度锁** 并行插入
- 搜索时用 **Scratch 对象池** 消除线程竞争
- 动态更新用 **shared_timed_mutex 多级锁**（update / consolidate / tag / delete）

### 设计模式总结

| 模式 | 体现 |
|------|------|
| **Strategy** | 可插拔的 `Distance`、`DataStore`、`GraphStore` |
| **Factory + Builder** | `IndexFactory` + `IndexConfigBuilder` 构造正确的模板特化 |
| **Type Erasure** | `AbstractIndex` 用 `std::any` 桥接模板与非模板接口 |
| **Object Pool** | `ConcurrentQueue<Scratch*>` 复用搜索临时空间 |
| **Template Method** | `AbstractIndex::search()` 调度到子类 `_search()` |
| **Dependency Injection** | 向 Index 注入 DataStore / GraphStore 实例 |

---

### 常见误区

> **PQFlashIndex 并不是把内存索引简单搬到磁盘。** 它有完全不同的数据布局（扇区对齐）、距离计算方式（PQ 查表而非精确计算）和 I/O 模型（异步批量读取）。两者共享 Vamana 图构建算法，但搜索路径截然不同。
